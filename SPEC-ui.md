# pi-beads-lean: тихий init + виджет «в работе»

Спецификация переписывания. Составлена 2026-08-23 по итогам разведки
(`/tmp/beads-lean-research.md`, 718 строк, с прогонами `bd init` в `/tmp/bdprobe-{a,b,c}`).
Решения по развилкам приняты владельцем.

Все ссылки вида `src/index.ts:NNN` относятся к состоянию файла на момент составления.

## Задача 1. `/beads-init` не должен трогать файлы проекта

**Что не так сейчас.** Обработчик команды (`src/index.ts:708-717`) запускает `bd init`
без единого флага. Само расширение не пишет ни одного файла — весь мусор создаёт `bd` 1.0.5:
`AGENTS.md` (в существующий дописывается блок `<!-- BEGIN BEADS INTEGRATION -->`, 39 → 4041 байт),
`CLAUDE.md`, `.claude/settings.json` с хуком `SessionStart`, `.codex/config.toml` и
`.codex/hooks.json` с четырьмя хуками, `.agents/skills/beads/`, пять git-хуков в `.beads/hooks/`
с подменой `core.hooksPath`. Проверено прогоном.

**Изменение.** В `src/index.ts:711`:

```ts
const r = await bd(["init", "--skip-agents", "--skip-hooks"], activeCwd);
```

Прогоном подтверждено (`/tmp/bdprobe-b`), что с этими флагами не создаётся ничего из
перечисленного, а `core.hooksPath` остаётся незаданным.

**Почему это не потеря функциональности.** Инструкцию для агента расширение инжектит само
в `before_agent_start` (`src/index.ts:337-345`), а скилл `beads` поставляет через
`resources_discover` (`src/index.ts:320`). То, что кладёт `bd`, — дубликат.

**Принятый остаток** (решение владельца: принять, флагов против этого в `bd init --help` нет):
`git init` в не-репозитории, пять строк в корневом `.gitignore`, один коммит созданных файлов.
Упомянуть это в README одной фразой, чтобы не было сюрпризом.

## Задача 2. Футер сокращается до значка

**Что не так сейчас.** `setStatusLine` (`src/index.ts:305-316`) пишет через
`ctx.ui.setStatus("beads", text)` одну из трёх строк длиной 22, 17 и 29 символов.
Все расширения делят **одну** строку футера, склеиваемую через пробел и обрезаемую по ширине,
поэтому 29 символов отъедаются у остальных индикаторов.

**Изменение.** Текст сводится к значку, видимому всегда:

- beads готов (любая топология, umbrella или одиночный репозиторий) → `bd✓`
- beads не инициализирован → `bd✗`

Различие umbrella / CLI из футера уходит: оно статично и узнаётся командой `/beads`.
Подсказка `/beads-init` остаётся там, где от неё есть польза, — в `ui.notify`
(`src/index.ts:678`) и в выводе `/beads`.

Точки вызова `setStatusLine` не меняются: `session_start` (`:326`) и `/beads-init` (`:713`).

## Задача 3. Виджет задач, взятых в работу

**Механизм.** `ctx.ui.setWidget` — документирован в `docs/tui.md:798-817`: принимает массив строк
либо функцию отрисовки, поддерживает многострочность, снимается передачей `undefined`.
Размещение `{ placement: "aboveEditor" }`. Ключ виджета: `beads-wip`.

Именно так устроен образец `@juicesharp/rpiv-todo` (`todo-overlay.ts:66-81`): виджет, а не футер;
состояние в памяти; лимит строк с хвостом `+N more`; обрезка по ширине; скрытие при пустоте.

**Что показывается.** Шапка с фирменной иконкой и счётчиками, ниже — дерево задач:

```text
⦿ beads · 2 active · 1 done · 12 ready
├─ ◐ P1 crmback-1a2  [crm-backend] Починить экспорт счетов в PDF      14m
├─ ◐ P2 front-7x9    [crm-front]   Перерисовать шапку карточки паци…   3h
└─ ✓ P0 chub-3k1     [content-hub] Компактная шапка шага импорта
```

Потолок — 6 строк задач плюс шапка; лишнее уходит в хвост `+N more`. Первыми вытесняются
закрытые, как в `rpiv-todo`. Показывать нечего → `setWidget("beads-wip", undefined)` целиком,
вместе с шапкой.

**Иконки и цвета.** Образец — `@abix5/pi-hindsight`, `src/ui.ts:428-453`: фирменная эмодзи в
акцентном цвете плюс односимвольные глифы состояния, крашенные через тему.

| Элемент | Глиф | Цвет темы |
|---|---|---|
| иконка инструмента | `⦿` (бусина; эмодзи отвергнута — ширина зависит от шрифта) | `accent` |
| слово `beads` | — | `accent`, если есть активные; иначе `dim` |
| счётчики в шапке | — | `muted` |
| ветки дерева | `├─` / `└─` | `dim` |
| задача в работе | `◐` | `warning` |
| закрытая задача | `✓` | `success` |
| приоритет `P0` | — | `error` |
| приоритет `P1` | — | `warning` |
| приоритет `P2` и ниже | — | `muted` |
| идентификатор | — | `muted` |
| репозиторий в скобках | — | `dim` |
| заголовок задачи в работе | — | `text` |
| заголовок закрытой | — | `muted` + `strikethrough` |
| время в работе | — | `dim` |

Цвет берётся из темы, приходящей вторым аргументом фабрики виджета. **Сейчас этот аргумент
выброшен** (`src/index.ts`, фабрика объявлена как `() => ({...})`) — именно поэтому виджет
серый. Краску без темы (сырые ANSI-коды) использовать нельзя: пользовательские темы бывают
светлые.

**Железное правило ширины.** Вёрстка и обрезка считаются по **простому тексту-двойнику**, цвет
накладывается только на готовые куски после обрезки. Это прямой урок `pi-hindsight`
(`src/ui.ts:437-441`): фрагмент, измеренный в крашеном виде, измеряет управляющие коды и
ломает вёрстку. Эмодзи считается за две колонки (`src/ui.ts:56`).

**Закрытые задачи.** Живут на экране **один ход агента**, как в `rpiv-todo`
(`todo-overlay.ts:91-98`, `index.ts:287-289`): после отрисовки идентификатор помечается к скрытию,
на старте следующего хода убирается. Источник бесплатный: `beads_close` уже знает закрытые
идентификаторы. Счётчик `N done` в шапке — за всю сессию, а не за ход.

**Счётчик готовых.** `N ready` — из `bd ready --json` (отдельный подпроцесс, около 0.22 с).
Обновляется только при старте сессии и после записей в `bd`, никакого опроса по таймеру.
Не удалось получить — сегмент из шапки просто убирается; показывать `0 ready` вместо
неизвестности запрещено — это враньё.

**Приоритет и время в работе** берутся из уже выполняемого запроса `bd list --status in_progress
--json`: поля `priority` и `started_at`. Время показывается компактно: `14m`, `3h`, `2d`.
Нет `started_at` — колонка пустая.

**Откуда берутся задачи.**

1. При старте сессии — один раз подтянуть уже висящие `in_progress` по каждому известному
   репозиторию, переиспользуя существующий путь `bd list --status in_progress`
   (`src/index.ts:279`). Запрос не должен блокировать `session_start`: ошибка или отсутствие
   `bd` гасится молча, виджет просто остаётся пустым.
2. Дальше — по факту записи: в ветке успеха `beads_update` (`src/index.ts:558-560`)
   при `status === "in_progress"` задача добавляется, при любом другом статусе — снимается.
   В `beads_close` (`src/index.ts:591-594`) снимаются все закрытые идентификаторы.

Заголовок задачи в `beads_update` неизвестен. Брать его одним вызовом уже существующего пути
`bd show` в момент добавления и класть в кэш; перевод задачи в работу — событие редкое,
лишний подпроцесс здесь допустим. Пока заголовок неизвестен — показывать строку без него.

**Состояние.** `Map` в памяти расширения, ключ — идентификатор задачи, значение — репозиторий
и заголовок. Ни диска, ни опроса `bd` по таймеру. Переживание `/reload` не требуется.

**Техническая деталь.** Сейчас `ctx.ui` наружу из `session_start` не сохраняется
(`src/index.ts:322-330`), а виджет надо обновлять из обработчиков инструментов. Сохранить ссылку
на `ctx.ui` в переменной модуля и обращаться к ней защищённо: в неинтерактивных запусках
(подагенты, workflow) `ui` может отсутствовать, и это не ошибка.

## Чего делать НЕ надо

Не показывать созданные и готовые к работе задачи — только взятые в работу.
Не опрашивать `bd` периодически. Не хранить состояние на диске. Не трогать формат
инструментов `beads_*` и разбор идентификаторов по префиксам.

## Как проверить, что сделано

1. В пустом временном каталоге под `/tmp` выполнить `/beads-init` и убедиться, что
   `AGENTS.md`, `CLAUDE.md`, `.claude`, `.codex`, `.agents`, `.beads/hooks` отсутствуют,
   а `git config --get core.hooksPath` возвращает код 1.
2. В репозитории с уже существующим `AGENTS.md` выполнить `/beads-init` и убедиться, что
   md5 файла не изменился.
3. Перевести задачу в `in_progress` через `beads_update` — виджет появляется над строкой ввода
   и содержит идентификатор, репозиторий и заголовок. Закрыть её через `beads_close` — виджет
   исчезает.
4. Сузить окно терминала и убедиться, что строки обрезаются, а не переносятся.
5. Футер содержит `bd✓` или `bd✗` и ничего больше.
